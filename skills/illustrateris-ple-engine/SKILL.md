# Illustrateris PLE Engine: Ejection, Removal & Lifecycle

`ple-engine` is a zero-dependency Rust procedural layout compiler (Context JSON -> Semantic Profiler -> OKLCH/APCA Palette -> BSP Spatial Grammar -> Cassowary LP Solver -> 12-Column HTML/CSS). While `ple-engine` solves geometry, typography, and contrast mathematically, keeping raw `ple-engine` footprints in a production frontend or bespoke WebGPU interface creates friction:

1. **Cryptic Class Hashes**: `--backend css` emits content-addressed `.ple-<16-hex>` selectors (e.g. `.ple-8f9a2b1c0d3e4f5a`) that are unreadable during manual styling or animation choreography.
2. **Repeated Inline Literals**: Raw output repeats `oklch(...)` literals across rules instead of exposing a central `:root` token layer.
3. **Generator Fingerprints**: Raw output injects `<meta name="generator" content="ple-engine ...">` and `<!-- ple-engine ... -->` comments.
4. **Binary Coupling**: Downstream frontend repositories should not require compiling a Rust binary (`cargo build`) just to iterate on UI components, WebGPU canvases, or motion.

Use this skill to **remove/eject `ple-engine`** (`De-PLE`) cleanly while preserving 100% of its mathematical invariants, or to operate `ple-engine` as a one-shot geometry solver before handoff.

## When to Use

- The user asks to **remove `ple-engine`** ("убрать ple engine", "strip ple-engine", "eject ple", "отвязать от ple-engine").
- You have HTML/CSS generated by `ple-engine` containing `.ple-<16hex>` classes and need clean `:root` CSS Custom Properties and human-readable selectors.
- You are transitioning a project from deterministic layout scaffolding to custom components (React, Next.js, Astro, Svelte, vanilla HTML + WebGPU).
- Rust/Cargo is unavailable in the environment and you must execute Illustrateris's mathematical layout & APCA rules directly in code without the `ple` binary.
- You need to compile Context JSON via `ple eject` or `ple compile` and verify geometry in headless Chromium.

## Steps

### 1. Choose the Removal / Ejection Mode

Select the exact path based on what exists in the workspace:

| Scenario | Action |
| --- | --- |
| **Existing `.html` / `.css` has `.ple-*` classes** | Run `python3 <skill>/scripts/eject_ple.py <file.html> --in-place` to strip all `ple-engine` comments/meta, extract `:root` OKLCH tokens, and rename `.ple-<16hex>` to semantic `.ui-*` classes. |
| **Compiling from Context JSON with `ple` binary** | Run `ple eject <context.json> -o index.html` (or `ple compile <context.json> --clean --backend css --no-cdn -o index.html`). This emits `:root` variables, `.ui-*` classes, and zero `ple-engine` fingerprints directly from Rust. |
| **Unbinding a frontend repo from the Rust crate** | Eject all generated pages via `eject_ple.py`, move the extracted `:root` tokens into your main stylesheet, and remove `ple` build hooks from `package.json` / CI. |
| **No `ple` binary available (Zero-Binary Mode)** | Apply the 4 Illustrateris mathematical invariants (Section 3 below) directly in CSS/TypeScript without invoking `ple-engine`. |

### 2. Execute Clean Ejection (`De-PLE`)

#### A. Stripping `ple-engine` from existing HTML/CSS (No Rust needed)

Run the bundled Python ejector on any file generated by `ple-engine`:

```bash
python3 skills/illustrateris-ple-engine/scripts/eject_ple.py index.html -o index.clean.html
# Or modify in place:
python3 skills/illustrateris-ple-engine/scripts/eject_ple.py index.html --in-place
```

What `eject_ple.py` does deterministically:

1. Removes `<!-- ple-engine ... -->` provenance comments and `<meta name="generator" content="ple-engine...">`.
2. Scans all CSS rules and maps `.ple-<16hex>` hashes to semantic role selectors based on declaration signatures:
   - `.ui-section-N` (section containers)
   - `.ui-grid-N` (12-column CSS Grid wrappers)
   - `.ui-cell-N` (responsive `col-span-12` -> `@media (min-width: 1024px)` grid placements)
   - `.ui-type-N` (fluid `clamp()` typography rules)
   - `.ui-btn-N` (interactive controls)
   - `.ui-canvas-N` (WebGPU `<canvas>` surfaces)
   - `.ui-stack-N` (flex containers)
3. Deduplicates all `oklch(...)` literals into a clean `:root` block (`--color-bg`, `--color-surface`, `--color-text`, `--color-border`, `--color-text-muted`, `--color-accent`, `--color-accent-text`) and rewrites rule declarations to `var(--color-*)`.

#### B. Native Rust CLI Ejection (`ple eject`)

If compiling from a Context JSON file with the upgraded `ple-engine` (`v0.2.0+`):

```bash
cargo run --release -- eject examples/webgpu-flagship.json -o index.html --report report.json
```

`ple eject` forces `--clean --backend css --no-cdn`, emitting `:root` custom properties (`--bg`, `--surface`, `--border`, `--text`, `--text-secondary`, `--accent`, `--accent-text`, `--font-family`, `--radius`), `.ui-<8hex>` classes, and zero `ple-engine` metadata.

### 3. Zero-Binary Mode (Replacing `ple-engine` with Native Math)

When `ple-engine` is removed from the stack, never fall back to arbitrary template guesses. Enforce the four mathematical invariants of `ple-engine` directly in your frontend code:

1. **Perceptual OKLCH + APCA Contrast (`|Lc|`)**:
   - Define palette tokens in `oklch(L C H)`.
   - Dark theme ground: `L = 0.14`, surface: `L = 0.18`, chroma `0.012..0.052`.
   - Light theme ground: `L = 0.985`, surface: `L = 0.955`, chroma `0.004..0.016`.
   - Enforce APCA `|Lc|` minimums across both `bg` and `surface`:
     - Body copy: `|Lc| >= 90`
     - Secondary text, labels, button text: `|Lc| >= 75` (in dark mode, `L` must be `>= 0.84`, never `0.70`)
     - Display headlines: `|Lc| >= 60`
     - Accent fills vs ground: `|Lc| >= 45`
     - Hairline borders: `|Lc| >= 12`

2. **Harmonic Scale & Analytic Leading**:
   - Pick one scale ratio `r` from `{1.250, 1.333, 1.414, 1.618}` based on domain drama.
   - Base spacing unit: `4px` (high density) or `8px` (editorial/spacious). Quantize all spacing to multiples of the base unit.
   - Fluid typography via `clamp(min_rem, offset_rem + slope_vw, max_rem)` between `320px` and `1440px`.
   - Analytic line-height (never arbitrary constants):
     - Display / Metric: `LH = 0.78 + 0.40 / sqrt(size_rem)` (e.g. `6.2rem` -> `0.94`)
     - Heading (`h2`): `LH = 0.90 + 0.45 / sqrt(size_rem)`
     - Body copy: `LH = 1.00 + 0.55 / sqrt(size_rem)` (`1.0rem` -> `1.55`)

3. **12-Column Grid & Reading Order Invariant**:
   - Every section uses `display: grid; grid-template-columns: repeat(12, minmax(0, 1fr));`.
   - Below `1024px`, all children span `1 / -1` (`col-span-12`). Desktop column placements (`grid-column: S / span W`) apply at `@media (min-width: 1024px)`.
   - DOM order must equal visual order and keyboard focus order (WCAG 1.3.2). Never use negative `order` or out-of-sequence `grid-row` jumps that scramble tab navigation.

4. **2D Visual Mass Balance & Entropy Damping**:
   - Visual mass of a block: `M = InkArea * (|Lc| / 100) * (Weight / 400)`.
   - Keep horizontal centre of mass `cx` within `|cx - 0.5| <= 0.15` (`[0.35, 0.65]`).
   - **Entropy Damping**: If Section `i` has high asymmetry (`imbalance > 0.60`, e.g. a dramatic `8/4` or `9/3` split hero), Section `i + 1` MUST damp to structural calm (`[0.20, 0.40]`, e.g. balanced metric row or symmetric split). Never stack two chaotic asymmetric sections back-to-back.

### 4. Verify Geometry After Removal

After ejecting or removing `ple-engine`, verify that no horizontal overflow, box escape, or contrast regression was introduced:

```bash
python3 verify/browser_verify.py --html index.clean.html --viewport 1440,768,375
# or gate on it directly (exits non-zero on a dirty page):
sh verify/run.sh index.clean.html
```

Confirm in the JSON output that `horizontal_overflow_px == 0` at all three viewports, that all `<section>` descendants remain contained within their parent bounds, and that `overflowing_elements` is empty. The last one matters because sections are `overflow: hidden`: content wider than its own box (a long unbreakable identifier or path, a chip with a 40-character package id) is **clipped** rather than reported as page overflow, so the page can pass the first two checks while the card is visibly cut off.

## Gotchas

- **Never delete the CSS reset when stripping `ple-*` classes**: `box-sizing: border-box` and `margin: 0` on headings/figures are required so `width: 100%` sections with horizontal `padding` do not overflow the viewport by `2 * pad_x`.
- **Preserve explicit `font-family` on `<button>` and `<input>`**: Browsers do not inherit `font-family` into form controls unless `input, button { font: inherit }` or explicit control rules remain intact.
- **Do not leave orphaned `data-webgpu-shader` canvases unstyled**: When ejecting a layout that uses `visual_anchor: "webgpu_canvas"` or `role: "media"`, keep the `aspect-ratio` rule on `<canvas>` so the layout does not collapse to `300x150` before the WebGPU device initializes.
